# LX-16A 总线舵机协议

> 本文档基于官方《02 总线舵机通信协议》PDF + **实机验证**。

---

## 物理层

| 项目 | 参数 |
|---|---|
| 接口 | 半双工 UART 异步串行总线 |
| 波特率 | **115200 bps**（默认） |
| 电平 | TTL |
| 拓扑 | 链型，理论最多 253 个舵机 |

**接线（3 线）**：`GND / VIN / SIG`（引脚顺序自左向右）

---

## 帧格式

```
┌──────┬──────┬────┬────────┬─────┬────────────┬──────────┐
│ 0x55 │ 0x55 │ ID │ Length │ Cmd │ 参数...     │ Checksum │
└──────┴──────┴────┴────────┴─────┴────────────┴──────────┘
  帧头(2)       1     1        1      N            1
```

### 关键规则（最容易搞错的地方）

> **数据长度 Length + 3 = 整包长度**（从帧头到校验和）
>
> **Length = ID(1) + Cmd(1) + 参数长度 + Checksum(1)**

### 校验和

```
Checksum = ~(ID + Length + Cmd + Prm1 + ... + PrmN) & 0xFF
```

### ID

- 范围：0 ~ 253
- **254 (0xFE) = 广播**（所有舵机执行，但不返回应答，避免总线冲突）

## 官方例子（实测验证）

### 1. 舵机转到 500，时间 1000ms

```
55 55 01 07 01 F4 01 E8 03 16
       ↑  ↑  ↑  ↑─────┬────┘  ↑
       ID 长 令  角度  时间   校验和
          7    500   1000
```

**校验和计算**：
```
sum = 01 + 07 + 01 + F4 + 01 + E8 + 03 = 0x1E9
    & 0xFF = 0xE9
~0xE9 = 0x16  ✓
```

### 2. 舵机转到 1000，时间 300ms

```
55 55 01 07 01 E8 03 2C 01 DE
```

### 3. 读位置（指令 28）

发送：
```
55 55 01 03 1C 73
```

应答（实测）：
```
55 55 01 05 1C EA 03 F0
       ↑  ↑  ↑  ↑─────┘
       ID 长 令  位置 = 0x03EA = 1002
```

**应答的 Length = 5**（ID 1 + Cmd 1 + 参数 2 + 校验 1）

### 4. 改 ID（指令 13）

把 ID=1 的舵机改成 ID=2：
```
55 55 01 04 0D 02 EB
```

⚠️ **总线上如果有多个同 ID 的舵机，改号会同时改掉所有！**
所以必须**单独接一个舵机**来改号。

## 参数范围

| 参数 | 范围 | 说明 |
|---|---|---|
| 角度 | 0 ~ 1000 | 对应 0 ~ 240°，最小分辨率 0.24° |
| 时间 | 0 ~ 30000 ms | 在该时间内匀速转到目标角度 |
| ID | 0 ~ 253 | 254 = 广播 |
| 电压限制 | 4500 ~ 14000 mV | 超出会 LED 闪烁 + 卸载电机 |
| 温度限制 | 50 ~ 100 °C | 默认 85°C，超出会卸载电机 |

---

## ⚠️ 舵机的自我保护

| 触发条件 | 行为 | 恢复 |
|---|---|---|
| 输入电压超出范围 | LED 闪烁，**电机卸载（无力矩）** | 电压恢复后自动 |
| 内部温度 > 85°C | LED 闪烁，**电机卸载** | 冷却后自动 |
| 收到 LOAD_OR_UNLOAD_WRITE(0) | 无力矩 | 发 1 重新装载 |

**注意**：舵机出厂时「装载状态」默认是 **0（卸载）**，但实测位置控制指令能直接让它动。

## 舵机的机械范围

- 位置 0~1000 对应 0~240°
- **顶到限位时会有负过冲**（读位置返回 0xFFFE = -2）
- 所以解析时要处理有符号数：

```python
v = data[i+5] | (data[i+6] << 8)
return v - 65536 if v > 32000 else v
```

## STM32 端的实现

```c
static void servo_send_frame(uint8_t id, uint8_t cmd, const uint8_t *params, uint8_t plen)
{
    uint8_t len = plen + 3;          /* ID + CMD + 参数 + 校验和 */
    uint16_t sum = id + len + cmd;
    for (uint8_t i = 0; i < plen; i++) sum += params[i];

    pa2_drive(1);                    /* 推挽输出 */
    u2_putc(0x55); u2_putc(0x55);
    u2_putc(id);
    u2_putc(len);
    u2_putc(cmd);
    for (uint8_t i = 0; i < plen; i++) u2_putc(params[i]);
    u2_putc((~sum) & 0xFF);

    while (!(USART2->SR & USART_SR_TC)) { }   /* 等最后一个字节移出 */
    pa2_drive(0);                    /* 切高阻 */
}

/* 位置控制 */
static void servo_move(uint8_t id, uint16_t pos, uint16_t time_ms)
{
    uint8_t p[4] = {
        pos & 0xFF,     pos >> 8,
        time_ms & 0xFF, time_ms >> 8
    };
    servo_send_frame(id, 1, p, 4);   /* 指令 1，4 字节参数 → Length=7 */
}
```

## 💡 最大教训

**第一版实现多加了「速度」2 个字节**，导致：
- Length 算成 7（应该是 5 + 2 = ... 反正错了）
- 帧长度 12 字节（正确是 10）
- **舵机静默丢弃整个包，完全没有任何反应**

排查花了近 1 小时。**教训：协议文档一定要逐字节核对，写完先用官方例子对比。**
