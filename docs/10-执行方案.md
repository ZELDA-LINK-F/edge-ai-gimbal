## 0 · 一句话

**先改三个常数（1 小时，砍掉约 240ms），再接 engine（省 10ms），再上 60fps，最后绕开 ultralytics 才能吃到 4.5ms 的推理。**
09 里"先搞相机管线再搞模型"的顺序要调过来——实测 PyTorch 一帧 30ms，比 60fps 的 16.7ms 帧周期还长，先上 60fps 只会丢帧。

## 1 · 实测基线（2026-10-20 21:00，MAXN_SUPER）

| **TensorRT 纯计算（trtexec）** | **4.0ms** compute / 4.5ms latency / 250 qps | 640×640 FP16，`lab1/yolov8n_fp16.engine` |

| 环境 | TRT 10.3.0 / torch 2.5-nv / ultralytics 8.3.213 / nvcc 12.6 | |

### 三个由此得出的关键判断

1. **engine 只省 10.5ms，不是 26ms** —— 因为 ultralytics 的前后处理（letterbox + NMS + Python）占了约 **15ms**。
   想拿到 4.5ms 的推理，必须**绕开 ultralytics 自己写 TRT runner**（Phase 4）。
2. **现有 engine 的类别名是 `class0 … class79`**（trtexec 转的，没有元数据）。
   `follow.py` 里 `d["class"] == "person"` **会永远匹配不到** —— 直接接 engine 会让跟随**静默失效**。
   必须先解决（Phase 2）。
3. **60fps 硬件可用**已确认，但只有 loop 能压到 16.7ms 以内才吃得满（P≤8ms 时）。

## Phase 0 · 建基线（半天，必须先做）

### 0.1 给 `follow.py` 加打点

在 `step()` 里插时间戳，每 300 帧打印 p50/p95：

```python
import time, statistics

class Prof:
    def __init__(self, every=300):
        self.d = {}; self.n = 0; self.every = every
    def add(self, k, ms):
        self.d.setdefault(k, []).append(ms)
    def tick(self):
        self.n += 1
        if self.n % self.every: return
        out = []
        for k, v in self.d.items():
            v = sorted(v); n = len(v)
            out.append("%s p50=%.1f p95=%.1f" % (k, v[n//2], v[min(n-1, int(n*0.95))]))
            self.d[k] = []
        print("[prof] " + " | ".join(out), flush=True)
```

`step()` 内：

```python
t0 = time.perf_counter()
ok, frame = self.cap.read()
t1 = time.perf_counter()
if self.flip: frame = cv2.rotate(frame, cv2.ROTATE_180)
t2 = time.perf_counter()
dets, _ = detect_frame(self.model, frame, conf=CONF)
t3 = time.perf_counter()
# ...筛选/映射/限位/发串口...
t4 = time.perf_counter()

self.prof.add("grab",    (t1-t0)*1000)
self.prof.add("rotate",  (t2-t1)*1000)
self.prof.add("infer",   (t3-t2)*1000)
self.prof.add("ctrl+tx", (t4-t3)*1000)
self.prof.add("loop",    (t4-t0)*1000)
self.prof.tick()
```

> 只看均值没有意义，控制环怕的是 p95 抖动。

### 0.2 舵机阶跃响应（`servo_step.py`）

`servo.py` 的 `cmd()` 固定等 0.4~0.6s，不能用来采样。用下面这个直接写串口 + 50ms 轮询读位置：

```python
#!/usr/bin/env python3
"""舵机阶跃响应：S1,<target>,<ms> 之后每 ~50ms 读一次位置"""
import sys, time, serial
from servo import ServoBus  # 复用找端口/限位逻辑

bus = ServoBus()
print("port:", bus.port)

def raw_read(sid):
    bus.s.reset_input_buffer()
    bus.s.write(("R%d\r\n" % sid).encode())
    t0 = time.time(); buf = b""
    while time.time() - t0 < 0.12:
        buf += bus.s.read(256)
    txt = buf.decode("utf-8", "replace")
    for line in txt.splitlines():
        if "字节" not in line: continue
        try:
            data = [int(h, 16) for h in line.split(":")[1].split()]
        except Exception:
            continue
        for i in range(len(data) - 7):
            if data[i:i+3] == [0x55, 0x55, sid] and data[i+3] == 0x05:
                v = data[i+5] | (data[i+6] << 8)
                return v - 65536 if v > 32000 else v
    return None

start, target = 500, 550
bus.s.write(("S1,%d,1000\r\n" % start).encode()); time.sleep(1.5)
for ms in (50, 200):
    bus.s.write(("S1,%d,1000\r\n" % start).encode()); time.sleep(1.5)
    t0 = time.time()
    bus.s.write(("S1,%d,%d\r\n" % (target, ms)).encode())
    samples = []
    while time.time() - t0 < 0.8:
        p = raw_read(1)
        samples.append((round((time.time()-t0)*1000), p))
    print("ms=%d:" % ms, samples)
bus.close()
```

**判读**：从开始到位置到达 `target±2` 的耗时。若 `ms=200` 约 200ms、`ms=50` 约 50ms，
就证明 09 的"ms = 滞后"模型成立，Phase 1 的收益预测可信。

> 采样分辨率受 STM32 的 R 命令限制（内部等 50ms），只能分辨 50ms 级差异。
> 要更准就用手机 240fps 慢动作拍舵机臂，数帧数 × 4.17ms。

## Phase 1 · 控制参数（1 小时）★ 收益最大

`follow.py`：

```python
SMOOTH  = 0.25   →  TAU = 0.030      # 改成时间常数
MOVE_MS = 200    →  MOVE_MS = 50
                       DEADBAND = 4  # 新增，1° 死区
```

`step()` 改为（完整版，含 dt 自适应与步长保护）：

```python
def step(self, verbose=False):
    t0 = time.perf_counter()
    dt = max(t0 - self.t_prev, 1e-3)
    self.t_prev = t0

    ok, frame = self.cap.read()
    if not ok:
        return None
    if self.flip:
        frame = cv2.rotate(frame, cv2.ROTATE_180)

    dets, _ = detect_frame(self.model, frame, conf=CONF)
    person = self.biggest_person(dets)
    self.frames += 1

    if person:
        self.hits += 1
        x1, y1, x2, y2 = person["box"]
        cx = (x1 + x2) / 2.0
        offset = max(-1.0, min(1.0, (cx - W / 2.0) / (W / 2.0)))
        target = PAN_CENTER + offset * (PAN_MAX - PAN_MIN) / 2.0
    else:
        target = PAN_CENTER

    if abs(target - self.pan) < DEADBAND:
        target = self.pan

    alpha = 1.0 - math.exp(-dt / TAU)
    want = self.pan + (target - self.pan) * alpha

    # 每帧最大步长：保护 FPC 排线，防止大跳变时舵机猛甩
    MAX_STEP = 12.0
    self.pan += max(-MAX_STEP, min(MAX_STEP, want - self.pan))

    self.send_move(self.pan)
    ...
```

- `__init__` 加 `self.t_prev = time.perf_counter()`，文件头补 `import math`
- "没人回中"那一行（`follow.py:131`）的 `400` 也改成 `MOVE_MS`

**验收**：`loop` p50 不变（还是 30ms 左右），但体感明显变快。
**风险**：抖动 → 先把 `DEADBAND` 4→6，不要急着把 `TAU` 调回去。

## Phase 3 · 相机 60fps（2 小时）

`follow.py` 与 `camera.py` **两条管线都要改**（`detect.py camera` 用的是 `camera.py.frames()`）：

```python
W, H = 1280, 720
FPS = 60
pipeline = (
    "nvarguscamerasrc sensor-id=0 aeantibanding=2"
    " exposuretimerange=\"1000 8000000\" gainrange=\"1 16\""
    " ! video/x-raw(memory:NVMM),width=%d,height=%d,framerate=%d/1,format=NV12"
    " ! nvvidconv ! video/x-raw,format=BGRx ! videoconvert"
    " ! video/x-raw,format=BGR ! appsink drop=1 max-buffers=1 sync=false"
    % (W, H, FPS)
)
```

| 改动 | 收益 |
|---|---|
| framerate 30→60 | T/2 16.7 → 8.3ms |
| max-buffers 2→1 | 消除最多 1 帧的排队 |
| sync=false | 不跟管线时钟 |
| exposure 上限 8ms | 暗光下自动曝光不会拉满一帧 |
| 删 rotate | 1.3ms |

**验收**：`grab` p50 ≈ **16.7ms**；`loop` ≈ 23ms（P=20 时跟不上 60fps，但不影响取最新帧）。
**风险**：曝光压太短 → 噪点、远处漏检。先在现场亮度下测 100 帧检出率；掉得多就把上限放到 12ms。

## Phase 4 · 自定义 TRT runner（1 天）★★ 第二收益

**为什么**：19.8ms 里有 15ms 是 ultralytics 的 letterbox/NMS/Python。自己写可以压到 **~8ms**。

要做的四件事：

1. **预分配**：一次创建 `IExecutionContext` + 固定输入输出显存，循环里不再 malloc。
2. **预处理进 GPU**：`cv2.resize` 到 640×640（或 640×360 + padding）后 `cudaMemcpy`，
   或者用 CUDA 核直接 BGR→RGB float CHW 写进 binding。
3. **后处理向量化**：输出 `1x84x8400` → numpy 一次算完 `conf = obj * cls`，`np.where(conf > thres)`，
   不要写 Python 循环。
4. **NMS**：`cv2.dnn.NMSBoxes` 或 torchvision（板子上都有）。

**验收**：`infer` p50 **< 10ms**；同一批图与 ultralytics 版检出框一致（IoU 比对）。
**风险**：NMS/坐标还原写错 → 框偏移。用 10 张固定图做回归对比。

## Phase 5 · 前馈（半天）

```python
# 目标速度估计（低通必须有）
raw_v = (target - self.target_prev) / dt
self.v = 0.75 * self.v + 0.25 * raw_v
self.target_prev = target

LEAD = TAU                       # 先用 30ms
lead = max(PAN_MIN, min(PAN_MAX, target + self.v * LEAD))

alpha = 1.0 - math.exp(-dt / TAU)
self.pan += (lead - self.pan) * alpha
```

**验收**：匀速横穿画面时稳态误差 ≈ 0，不振荡。
**风险**：框抖动被放大 → 低通不能省；目标消失瞬间 `lead` 必须 clamp（否则冲出去）。
